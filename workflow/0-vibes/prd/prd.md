# PRD — Task Tracker MCP

Формат — по аналогии с `0-vibes/prd/prd.md` из `regagro-workflow-demo`.
Реконструирован по факту (см. `../raw/2026-09-01.txt`).

## Проблема

Пользователю нужен свой аналог референсного MCP-сервиса (`queue-assignment`),
но под задачи, а не под электронную очередь: место, где и человек (через
REST/UI), и AI-агент (через MCP) видят один и тот же список задач и могут
им управлять.

## Требования (R)

| # | Требование |
|---|---|
| R1 | Пользователь регистрируется и логинится (Sanctum `access_token`) |
| R2 | Пользователь создаёт/читает/меняет/удаляет задачи через REST API |
| R3 | Задача имеет статус (`todo`/`in_progress`/`done`/`cancelled`) с ограниченными переходами |
| R4 | Задачу можно назначить на пользователя (`assignee_id`) |
| R5 | Пользователь видит и меняет задачи через веб-интерфейс `/tasks` |
| R6 | Пользователь выпускает отзываемый MCP-токен, независимый от `access_token` |
| R7 | MCP-агент (Claude Code и т.п.) читает/создаёт/меняет/удаляет задачи через MCP-инструменты, используя MCP-токен |
| R8 | Изменение, сделанное через любой из интерфейсов (REST/UI/MCP), видно во всех остальных (общая БД) |

## Решение

Laravel-приложение с одной моделью `Task` (единый источник правды),
доступной через три интерфейса на одной БД: REST API, веб-интерфейс `/tasks`,
MCP-сервер (`/api/mcp`, JSON-RPC 2.0).

## Границы (out of scope)

- Разделение задач по проектам/командам — не требовалось, плоский список.
- Полноценный OAuth 2.0 для MCP — отложено (см. `../raw/2026-09-01.txt`),
  пока достаточно статического токена + Claude Code CLI.
- Уведомления, дедлайны, вложения — не запрашивались.
